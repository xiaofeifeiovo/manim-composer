# 视听脚本与配音时间轴

## 制作顺序

用户原文 → 完整视听脚本 → 逐句配音 → 实测句子时间戳与完整音轨 → 按时间轴制作动画 → 合成检查。

`scenes.md` 供人阅读；`video_script.json` 供配音和动画读取。两者表达同一份脚本，不分别维护互相矛盾的旁白。每条 `sentences` 是一句实际朗读内容；逗号、分号、小数点不机械拆句，必要的长句先改写成自然短句。句子 ID 在修改过程中保持稳定；删除句子时停用原 ID，不把它转给不同句子。

## 解释目标与场景规划字段

新稿在全片层记录 `learning_goal`，写明观众看完能够解释、预测或判断什么；有贯穿例子时用 `through_example` 记录，没有则省略。

新稿还记录以下教学结构。它们用于保证解释完整，不送入 TTS：

| 全片字段 | 内容 |
|---|---|
| `modules` | 主题模块数组；每项含 `id`、`title`、`question`、`definition`、`inputs`、`outputs`、`scene_ids`、`opening_cue_ids`、`summary_cue_ids`、`summary`，以及有后续模块时的 `next_module_reason`。单主题短片可只有一个模块。开题和总结的 cue 必须真正讲述这些内容，不能只有元数据。 |
| `notation_conventions` | 全片基础约定：序列如何表示、行/列和堆叠方向、索引分别枚举什么、参数与变化的输入如何区分等。只记录本片相关约定。 |
| `notation` | 符号表数组；每项含 `symbol`、`meaning`、`type_shape`、`scope`、`definition_cue_id`。索引含义写入 meaning 或 conventions；存在别名时记录 `aliases` 并说明对应。维度尚未固定时用已定义的参数表示。 |

开头先用例子和画面定义基础表示，再进行相关运算；后续专业符号在首次使用前按需定义。符号表是作者的完整登记，不要求开头一次讲完全部符号。只有符号出现在屏幕上、没有语义解释，不算定义。

每场在现有 `id`、`title`、`source` 和 `sentences` 之外记录以下规划字段，并在 `scenes.md` 中保持一致：

| 字段 | 内容 |
|---|---|
| `module_id` | 所属主题模块 |
| `purpose` | 本场怎样推进全片理解目标 |
| `question` | 本场回答的具体问题 |
| `observation_task` | 希望观众通过变化或比较发现什么 |
| `incoming_state` | 入场时有哪些对象，哪些从前场沿用 |
| `key_operation` | 对谁做什么操作，哪些条件或量保持不变 |
| `outgoing_state` | 结束时保留的结果、对象或条件 |
| `uses_symbols` / `defines_symbols` | 本场使用/首次定义的符号，对应全片符号表；不涉及符号的场景可为空数组 |
| `continuity` | 使用前场结果时逐项记录 `from_scene`、`carried_object`、`identity` 和 `handoff`；identity 写明标签、索引、数值/形状，handoff 写明怎样在画面上接过该对象及下一步如何使用。开场或无依赖时为空数组；独立新例子要说明切换理由。 |

需要明确衔接时补充 `prior_understanding`（已有理解）、`new_content`（新增概念或条件）、`next_question`（下一段的来由）。这些字段用简明字符串即可；目标已经完成时，`next_question` 可省略或为空，不强行制造后续问题。

更新旧稿时，补齐当前修改场景所需的规划信息，保留已有句子 ID 与旁白。增加这些规划字段本身不要求重新配音；改变口述或停顿时才更新相应音轨。规划字段不进入 TTS，不改变 `scenes[].sentences[]` 的消费方式。

“保留旁白”只适用于纯规划或视觉修订。若旧稿缺少动机、定义、推导衔接或模块总结，必须补写必要句子并重新生成受影响的声音与时间轴，不能为了复用旧音轨而仅在元数据中补齐解释。

## video_script.json

下面只示范局部加权场景的逐句格式，省略上表的全片模块、符号表及本场衔接字段。它不是包含完整开题、定义和总结的可投产讲稿；实际新稿须补齐上述字段及对应旁白和画面。

```json
{
  "title": "加权求和怎样汇集信息",
  "learning_goal": "能从各输入向量及其权重，解释合成输出的来源",
  "through_example": "三个二维向量按给定权重合成一个输出向量",
  "scenes": [
    {
      "id": "s01",
      "title": "计算一个输出向量",
      "source": "用户文档：注意力加权求和小节",
      "purpose": "把权重与向量的逐元素乘加对应起来",
      "question": "各输入怎样共同形成一个输出向量？",
      "prior_understanding": "知道向量坐标、数乘和向量相加",
      "new_content": "按权重缩放后进行合成",
      "observation_task": "看到各向量缩放后对输出的具体贡献",
      "incoming_state": "显示三个输入向量及其给定权重",
      "key_operation": "保持输入与权重不变，先分别数乘，再将结果相加；移动副本保留原向量参照",
      "outgoing_state": "保留缩放后的三个分量与标有坐标的输出向量",
      "sentences": [
        {
          "id": "s01_001",
          "narration": "先把三个值向量，分别乘以零点二、零点三和零点五。",
          "subtitle": "先把三个值向量，分别乘以 0.2、0.3 和 0.5。",
          "screen_text": ["顶部标题：按权重缩放", "向量旁：(1,0)、(0,2)、(2,2)"],
          "screen_notes": [
            {"text": "数值为教学示意", "placement": "图右下角小字", "lifetime": "本场景结束时消失"}
          ],
          "animation": "本句开始显示三条值向量及对应权重；依次缩放各向量，保留缩放结果。",
          "pause_after": 0.2
        },
        {
          "id": "s01_002",
          "narration": "再把对应坐标相加，得到输出向量一点二、一点六。",
          "subtitle": "再把对应坐标相加，得到输出向量 (1.2, 1.6)。",
          "screen_text": ["结果框：(1.2, 1.6)"],
          "screen_notes": [],
          "animation": "承接上一句；把缩放后的箭头首尾相接，标出输出端点并高亮坐标相加的结果。保留上一句的小字。",
          "pause_after": 0.5
        }
      ]
    }
  ]
}
```

`narration` 是唯一进入 TTS 的字段。`subtitle` 仅显示这一句的对应内容；不能把 `screen_notes` 拼入字幕或旁白。标题、公式、标签、注释和动作均只供画面使用。上述数值、停顿和两句结构只是格式示例，不固化成每个项目的参数。

必要时给场景补充配色、布局和相机设计。公式在 `screen_text` 中可采用 LaTeX；JSON 中反斜线须正确转义。小字只需在有效期内显示一次，后续句子无需重复创建。

一个句子或短句组围绕一个主要思考动作，如建立对象、预测、观察或解释；无需添加固定的角色枚举字段。动画可以跨句连续发展，但每句仍写清其对应变化与保留状态。`pause_after` 仅安排确有观察或转场用途的停顿；需要说明用途时写在 `animation` 中，不把说明拼入旁白。

## 配音前的教学连贯性检查

- 按顺序读完整模块，确认开头明确主题、动机、宏观定义与输入输出，结尾用已建立的对象综合机制，而不是只有标题和术语清单。
- 将 `uses_symbols` 与符号表的定义位置对照：运算中不存在尚未解释的符号，序列、词元、向量和矩阵不会混称，索引和形状一致。
- 逐项追踪 `continuity`：前场确实产出了所填对象，后场确实用它继续推理。数值、行列、单位或身份不能无说明地改变；旁白与动作共同展示用途。
- 用一条具体输入到输出的链条检验观众能否解释每一步。增加元数据不能代替补写缺失的教学内容。
- 若说明所需篇幅超过预估，保留必要内容并更新时长预期；只有显式硬上限需要重新协调范围。不要为固定每章句数、镜头数或制作时间删掉连接。

## 声音阶段的交付

全部句子配音完成并核对全文后，才形成可用于动画的基准时间轴：

- `start`：本句在完整音轨中的开始时间。
- `end`：本句语音结束时间，由实际音频样本数测量。
- `window_end`：本句语音与显式停顿结束的时间，即下一句开始时间。
- `speech`、`duration`：语音本身时长、含停顿的时间窗长度。
- `audio`：本句的本地标准化音频；完整 master 音轨与逐句字幕同时生成。

按视频帧率向上对齐窗口，但不裁剪音频。句间停顿按叙述需要确定，不对所有句子添加冗长的统一留白，也不按将来的动画运行时间灌入最小时长。开场、转场和读公式所需停顿也必须计入这份音轨时间轴。

## 动画阶段的约束

动画可以在一句的窗口内设计展开过程；句子级时间戳不等于其中每个词的时间戳。需要精确到某个术语时，使用真实的对齐结果或把讲述拆成自然的独立句，不能把比例估算称为词级同步。

渲染只验证实际画面起点与基准时间的误差，不能重新决定旁白起点。分章渲染使用章内时间 = 全片时间减本章起点；章节时长必须覆盖已分配的全部窗口，拼接后再次核对。除非脚本明确安排，不在章节末尾额外加等待。若修改旁白或停顿，重新生成相应音频/音轨与下游时间轴；只修改小字或画面标签不触发 TTS。
